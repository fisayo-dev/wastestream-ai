# Contributing to WasteStream AI

Thanks for your interest in contributing! Contributions that improve documentation, fix bugs, add tests, or implement features are welcome.

Guidelines

- Issue first: Open an issue to discuss larger changes before implementing.
- Fork & branch: Create a topic branch from `main` or `onboarding` with a clear name: `feature/xxx`, `fix/yyy`, `chore/zzz`.
- One change per PR: Keep pull requests small and focused.
- Commit messages: Use present-tense, short summary, e.g. "feat(api): add user endpoint".
- Code style: Follow existing TypeScript formatting and ESLint rules. Run `npm run lint` in `web` and fix issues before submitting a PR.
- Tests: Add tests for new logic where feasible.
- Run locally: Before opening a PR, ensure the app runs locally and migrations are applied when touching database code.

How to contribute

1. Fork the repo and create a branch for your change.
2. Install dependencies and run the app locally (see README).
3. Make your changes on the branch and add tests where applicable.
4. Run linters and formatters, then commit and push to your fork.
5. Open a pull request describing the change and referencing any related issue.

Review process

- PRs will be reviewed by the maintainer. Expect feedback and iterate as requested.
- Keep PR descriptions clear and include screenshots or repro steps for UI changes.

Community

If you have questions or need help getting started, open an issue and tag the maintainer.

Thank you for improving WasteStream AI!
